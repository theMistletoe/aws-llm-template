# ADR 0006: ユーザー単位の利用回数上限（クォータ）と使用量表示を削除

- 状態: 採用
- 日付: 2026-10-30

## 決定

仕様 §8 のユーザー単位クォータ（生成 20回/日・10回/時、Web検索 20回/日、JST境界）と、§3 設定画面の「使用量表示」を**削除**した。キット利用者（オーナー）の判断による。

- 削除したもの: Usage行（`USER#<sub>` / `USAGE#D#…`・`USAGE#H#…`）と原子的カウンタ、`QUOTA_EXCEEDED`(429)、`GET /api/v1/usage`、設定画面の使用量、`QUOTA_*` / `USAGE_RETENTION_DAYS` の設定値、data テーブルの TTL（Usage行専用だったため）。
- 残したもの（安全のための制御で、使用量の管理ではない）: チャット単位の同時実行1本（ロック）、requestId による冪等性、入力 4,000文字、出力 2,048トークン、検索 3回/回答、コード送信のレート制限（60秒に1回・1時間に5回）。
- 生成のトークン数は、従来どおり各 assistant メッセージの `usage` と構造化ログ（`generation_finished`）に記録する。

## 影響

- ユーザー単位のコスト保護がなくなる。小規模・限定公開の前提では許容するが、一般公開時は WAF（`enableWaf` のレートベースルール）、Budgets、全体の上限などを検討すること（README・脅威モデルに明記）。
- 仕様 §8・§3・DoD #6 のクォータ部分からの意図的な逸脱。

## 再導入する場合

生成開始のトランザクション（`ChatRepository.startRun`）に、条件付き `ADD` のカウンタ更新を1件追加するのが最小の方法（git 履歴のコミット「ユーザー単位クォータの削除」以前の実装を参照）。
